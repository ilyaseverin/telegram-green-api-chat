# Telegram / GREEN-API

Минимальный React-клиент по тестовому заданию: подключение по `idInstance` и `apiTokenInstance`, создание чата по номеру или `@username`, отправка и получение **только текста**. Визуальный прототип — [MAX Web](https://web.max.ru/). Дополнительно по запросу загружаются имя контакта и история выбранного чата; подключение сохраняется при перезагрузке.

## Запуск

Нужен Node.js **22.13+**.

```bash
git clone https://github.com/ilyaseverin/telegram-green-api-chat.git
cd telegram-green-api-chat
npm ci
npm run dev
```

Откройте адрес Vite, обычно <http://127.0.0.1:5173>. Серверная база данных и переменные окружения не нужны.

## Подключение

1. Создайте Telegram-инстанс в [GREEN-API](https://console.green-api.com/) и авторизуйте Telegram. Состояние инстанса должно быть `authorized`.
2. Оставьте `webhookUrl` пустым. Включите `incomingWebhook` и `outgoingMessageWebhook` для входящих и сообщений с телефона. Для статусов доставки включите `outgoingWebhook`; также рекомендуются `outgoingAPIMessageWebhook` и `stateWebhook`. После изменения настроек подождите около минуты.
3. Введите ID и токен инстанса в приложении. Адрес API определяется по первым четырём цифрам ID; при необходимости его можно указать из кабинета.
4. Создайте чат по номеру с кодом страны или `@username`, если номер скрыт. Отправьте текст и ответьте из Telegram.

Приложение проверяет авторизацию, тип инстанса и обязательные настройки, не изменяя их автоматически.

## Как работает синхронизация

- `checkAccount` определяет Telegram `chatId`, `getContactInfo` загружает имя. При недоступном имени остаётся username или номер.
- При открытии чата `getChatHistory` запрашивает последние **100 сообщений** через GREEN-API. Отображается только текст. История объединяется с текущими сообщениями по ID без дубликатов. Повторная загрузка также происходит при возвращении во вкладку; периодического опроса истории нет.
- Новые сообщения поступают через один последовательный цикл `receiveNotification` → обработка → `deleteNotification`, как требует задание. Long polling завершается при появлении уведомления: `receiveTimeout=5` — максимальное время ожидания пустой очереди, а не задержка показа сообщений.
- Очередь GREEN-API общая для аккаунта; API не позволяет получать из неё только один чат. Приложение отображает новые сообщения **только созданных пользователем чатов**. Сообщения других диалогов и старые уведомления до подключения подтверждаются без добавления в интерфейс. История выбранного чата загружается отдельно.
- Поддерживаются входящие сообщения, исходящие с телефона и из API, а также статусы доставки. Накопленная очередь обрабатывается без искусственной паузы 400 мс после каждого уведомления. Большая очередь и задержки самого GREEN-API могут задерживать новые события; приложение не очищает очередь целиком.
- Временные ошибки получения повторяются с увеличением задержки и учётом `Retry-After`. Повреждённое уведомление остаётся в очереди, а интерфейс показывает ошибку. Неподдерживаемые вложения пропускаются с подтверждением.
- Отправка оптимистическая; автоматического повторения нет, поскольку при потере ответа сервер мог уже принять сообщение. Ручной повтор доступен с объяснением неопределённого результата.
- Чаты, активный диалог и подключение сохраняются в `sessionStorage` до выхода или закрытия вкладки. При восстановлении проверяется инстанс. Кеш ограничен 30 чатами и 100 сообщениями суммарно; серверная история дополняет его при открытии диалога. Недоступность хранилища не мешает обмену сообщениями.
- Выход отменяет запросы и очищает локальную сессию; сам Telegram-инстанс остаётся авторизованным. Web Locks не допускает двух потребителей очереди в одном браузере и origin. Другие устройства и интеграции должны использовать отдельный инстанс либо не читать ту же очередь.

Это клиентское тестовое приложение: браузер обращается к GREEN-API напрямую с введённым пользователем токеном. Токен не включён в исходники или сборку. Для общего служебного токена в публичном продукте нужен серверный посредник.

## Код и проверка

React + TypeScript + Vite. Zod проверяет внешние ответы, reducer управляет перепиской, небольшой контракт `ChatApi` отделяет HTTP-клиент от интерфейса. Глобальный store, роутер и UI-фреймворк не нужны для этого объёма.

```text
src/
  app/                 # композиция и общие стили
  api/                 # контракт, HTTP-клиент, валидация и ошибки
  features/auth/       # подключение и сохранение сессии
  features/chat/model/ # reducer, история, уведомления, кеш и React-хук
  features/chat/ui/    # диалоги, сообщения, форма отправки и новый чат
  shared/              # общие UI-компоненты и небольшие функции
  test/                # настройка тестового окружения
```

```bash
npm run check         # ESLint, Prettier, тесты, production-сборка
npm test
npm run test:watch
npm run build
npm run preview
npm run format
```

Тесты проверяют API, авторизацию и восстановление, историю, входящие и сообщения с телефона, фильтрацию диалогов, дубликаты, гонки статусов, отмену запросов и обработку ошибок. Для живой проверки нужны собственные данные Telegram-инстанса.

Верстка следует MAX Web: панель навигации, список чатов, поиск, активный диалог, голубой фон с узором и поле сообщения; есть адаптация для мобильного экрана. Источники узора и локального шрифта с лицензией указаны в `public/ASSETS.md`.
